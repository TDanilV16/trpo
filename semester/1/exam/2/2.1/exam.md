# Базы данных

## Виды первичных ключей. Какие требования прдъявляются к первичным ключам?

Первичный ключ -- это набор атрибутов, выбранных для идентификации уникальных экземпляров сущностей.
Атрибуты первичного ключа располагаются на линией в ключевой области
Пример -- номер сотрудника

### По структуре
- Простой ключ -- состоит из одного столбца (атрибута), который уникально идентифицирует каждую запись
- Составной ключ -- состоит из двух и более столбцов, комбинации значений, которые уникальны для каждой записи
Пример
primary key (student_id, course_id),
foreign key (student_id) references student.id
foreign key (course_id) references course.id

1. Две основные таблицы: Создаются две таблицы (например, Students и Courses) с их первичными ключами.
2. Промежуточная таблица: Создаётся третья таблица (например, StudentCourses), которая содержит:
   - Первичный ключ из первой таблицы (например, StudentID) как внешний ключ.
   - Первичный ключ из второй таблицы (например, CourseID) как внешний ключ. 
   - Составной первичный ключ из этих двух внешних ключей.

3. Связи: Устанавливаются две связи «один ко многим»:
   - От основной таблицы (например, Students) к промежуточной (StudentCourses). 
   - От второй основной таблицы (например, Courses) к промежуточной (StudentCourses). 

### По происхождени/смыслу
- Естественный ключ -- атрибут или набор атрибутов, которые уже существуют в реальном мире и имеют значения (номер паспорта)
- Сурогатный ключ -- искуственно созданный ключ, не имеющий бизнес-смысла, который используется для уникальной идентификации записей (надежный и не меняется) (guid автоинкремент)

### Требования к PK
- Уникальным образом идентифицировать экземпляр сущности
- Не использовать null значений
- Не изменяется со временем
- Быть как можно более коротким для использования индексирования и получения данных
