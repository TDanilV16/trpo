# Базы данных

## Колночные хранилища на примере MS SQL. Принцип работы, преимущества, механизмы обновления данных

Колночное хранилище в MS SQl реализуется через Columnstore index. В отличие от традиционного строкового хранения (rowstore),
данные сохраняются по столбцам, что позволяет эффективно выполнять аналитические запросы и экономить место.

### Принцип работы
- данные разбиваются на группы строк (rowstore)
- каждая группа хранится в виде column segments -- сегментов по столбцам
- используется batch mode execution -- пакетная обработка строк, ускоряющая выполнение запросов
- алгоритмы сжатия уменьшают объем данных

### Преимущества
- высокая производительность аналитики -- выборка только нужных столбцов
- экономия места -- сжатие данных
- гибкость применения -- поддержка как DWH сценариев, так и OLTP-нагрузки
- эффективная работа с большими данными -- оптимизация запросов типа sum, count, group by

###  Механизм обновления данных
- Delta Store -- новые строки сначала попадают в rowstore-структуру (Б-дерево). При накоплении они сжимаются и перемещаются в columnstore
- Delta Bitmap -- удаленные строки помечаются в специальной карте, физически остаются в сегменте до обслуживания
- Обновления -- реализуются как комбинация delete + insert. Старая версия строки помечается в delete bitmap, новая вставляется в delta store
